Documentation Rules

  1. Feature First: Mọi thay đổi phần mềm phải thuộc một Feature.
  2. Không lặp thông tin: Nội dung reusable phải reference thay vì copy.
  3. Rule riêng Feature ở Feature: Chỉ đưa Rule ra Catalog khi nhiều Feature dùng chung.
  4. Acceptance nằm gần Flow: Để Tester đối chiếu logic nhanh.
  5. Technical Detail chỉ tạo khi cần: Feature đơn giản không cần tài liệu API/DB riêng.
  6. Documentation là một phần của Done: Feature chưa cập nhật Docs thì chưa coi là hoàn thành.
  7. Document the behaviour, not the meeting: Chỉ ghi thứ ảnh hưởng tới nghiệp vụ hoặc cách hệ thống vận hành.
